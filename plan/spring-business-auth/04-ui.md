# 4. Login and private frontend state

## Goal and why
Demonstrate isolation without leaking the previous user's local chats.
## Files involved and exact changes
New auth service/context/login page and protected route. sessionStorage token and /me validation. requester centralizes authenticated JSON/SSE/blob fetch to the configured Spring origin only. Cache keys include user UUID; appBoot loads chats only after identity validation. Exit/401 abort requests and unmount/reset chat state; stale callbacks cannot update a new login. Knowledge images use authenticated Blob URLs and cleanup. Config model URL is the environment-derived Spring endpoint.
## Out of scope
Registration, redesign and old anonymous cache import.
## Done condition and verification
Login, reload, logout, A→B switch, 401, images and SSE/HITL tests pass; frontend build succeeds. Legacy keys preserved but never loaded.
## Expected output and next step
Browser demo ready for evidence collection.
## Risks
An old request's 401 must not log out a new session. Header merge ordering must preserve authentication.
