# Human-in-the-loop 可执行分步教程（RAG task 分解后确认）

本教程目标：在不改变整体 Workflow 顺序的前提下，把“任务拆解后人工确认”做成可暂停/可恢复的执行链。

---

## 1. 当前命中过程段落（Workflow Step）

- 命中 `Workflow: Agent 路由执行流程（RAG / Chat / Draw）` 的 Step 4 和 Step 5。
- 插入点是 `sub_question_generation -> evidence_collection` 之间。
- 参考：`software_recommend_system/Workflow.txt`

当前顺序（RAG 分支）：

1. `sub_question_generation`
2. `evidence_collection`
3. `evidence_evaluation`
4. `candidate_generation`
5. `coverage_check`

改造后顺序（RAG 分支）：

1. `sub_question_generation`
2. `human_confirmation`  (新增阻塞节点)
3. `evidence_collection`
4. `evidence_evaluation`
5. `candidate_generation`
6. `coverage_check`

---

## 2. 受影响节点与前后依赖

- 前置依赖节点
1. `query_normalization_node`：提供标准化查询与约束。
2. `sub_question_generation_node`：产出 `sub_questions`。

- 新增节点
1. `human_confirmation_node`：展示拆解结果并阻塞等待用户确认。

- 后置依赖节点
1. `evidence_collection_node`：依赖“最终确认后的 `sub_questions`”。
2. 后续循环控制（`coverage_check`）保持不变。

- 调用侧依赖
1. `POST /api/v1/recommend` 需要支持第一次调用可能返回 `awaiting_human_confirmation`。
2. 新增 `POST /api/v1/recommend/confirm` 用于 resume pipeline。

#### 2.2 新增函数（放在 `sub_question_generation_node` 后、`evidence_collection_node` 前）

新增代码：

```python
def _normalize_sub_questions(raw: Any) -> List[str]:
    if isinstance(raw, str):
        raw = [raw]
    if not isinstance(raw, list):
        return []
    cleaned = []
    for item in raw:
        text = str(item).strip()
        if text:
            cleaned.append(text)
    return cleaned


def human_confirmation_node(state: AgentState) -> Dict[str, Any]:
    """
    Human-in-the-loop 阻塞节点：
    1) 首次到达时通过 interrupt 暂停；
    2) 外部 resume 后拿到用户确认内容；
    3) 写回最终 sub_questions，继续后续检索流程。
    """
    original_sub_questions = _normalize_sub_questions(_get_field(state, "sub_questions", []))
    if not original_sub_questions:
        fallback_query = str(_get_field(state, "normalized_query", "")).strip()
        original_sub_questions = [fallback_query] if fallback_query else []

    request_payload = {
        "type": "human_confirmation",
        "query": _get_field(state, "user_query", ""),
        "sub_questions": original_sub_questions,
        "instruction": "请返回 JSON: {\"action\":\"confirm|edit\", \"sub_questions\":[...], \"comment\":\"...\"}"
    }

    human_input = interrupt(request_payload)

    action = str(_get_field(human_input, "action", "confirm")).strip().lower()
    if action not in {"confirm", "edit"}:
        action = "confirm"

    edited_sub_questions = _normalize_sub_questions(_get_field(human_input, "sub_questions", []))
    comment = str(_get_field(human_input, "comment", "")).strip()

    final_sub_questions = edited_sub_questions if action == "edit" and edited_sub_questions else original_sub_questions

    return {
        "sub_questions": final_sub_questions,
        "awaiting_human_confirmation": False,
        "pending_sub_questions": [],
        "human_feedback": comment,
    }
```

```

2. `interrupt(...)` 调用存在。

AGENT = create_rag_with_routing_agent()


def _get_value(result: Any, key: str, default: Any = None) -> Any:
    if isinstance(result, dict):
        return result.get(key, default)
    return getattr(result, key, default)


def _extract_interrupt_payload(result: Any) -> Optional[Dict[str, Any]]:
    if not isinstance(result, dict):
        return None
    interrupts = result.get("__interrupt__")
    if not interrupts:
        return None
    first = interrupts[0]
    payload = getattr(first, "value", first)
    if isinstance(payload, dict):
        return payload
    return {"type": "human_confirmation", "message": str(payload)}
```

#### 5.3 替换 `/recommend` 实现

@router.post("/recommend", response_model=RecommendationResponse)
async def get_software_recommendation(request_data: RecommendationRequest):
    try:
        session_id = request_data.session_id or uuid4().hex
        logger.info(
            "recommend request: session_id=%s timeout=%s max_iterations=%s query=%r",
            session_id,
            request_data.timeout,
            request_data.max_iterations,
            request_data.query,
        )

        state = AgentState(
            user_query=request_data.query,
            timeout_budget=request_data.timeout,
            max_iterations=request_data.max_iterations,
            start_time=time.time(),
            session_id=session_id,
        )

        config = {"configurable": {"thread_id": session_id}}
        result = await run_agent_async(AGENT, state, config=config)

        interrupt_payload = _extract_interrupt_payload(result)
        if interrupt_payload and interrupt_payload.get("type") == "human_confirmation":
            return RecommendationResponse(
                status="awaiting_human_confirmation",
                final_answer="",
                candidates=[],
                mode="rag",
                iteration_count=0,
                coverage=0.0,
                session_id=session_id,
                awaiting_human_confirmation=True,
                pending_sub_questions=interrupt_payload.get("sub_questions", []),
            )

        return RecommendationResponse(
            status="success",
            final_answer=_get_value(result, "final_answer", ""),
            candidates=_get_value(result, "candidates", []),
            mode=_get_value(result, "mode", ""),
            iteration_count=_get_value(result, "iteration_count", 0),
            coverage=_get_value(result, "coverage", 0.0),
            session_id=session_id,

## 6. 逻辑图（resume pipeline）

```text
POST /recommend
  -> create AgentState + thread_id
  -> ainvoke(state)
  -> sub_question_generation
  -> human_confirmation_node(interrupt)  -- 暂停并返回 sub_questions
  -> API 返回 awaiting_human_confirmation + session_id

POST /recommend/confirm
  -> ainvoke(Command(resume=human_input), same thread_id)
  -> human_confirmation_node 收到确认结果
  -> evidence_collection
  -> evidence_evaluation
  -> candidate_generation
  -> coverage_check (循环逻辑不变)
  -> answer_generation
  -> API 返回 success
```

---

## 7. 设计原因（为什么这样做）

1. 不改主流程顺序，只在 task 分解后插入一个门控节点，最小侵入。
2. 使用 LangGraph `interrupt/resume`，天然支持“暂停-恢复”而不是手写状态机。
3. 使用 `thread_id + checkpointer`，HTTP 两次请求可以衔接同一条执行链。
4. API 契约向后兼容：原本一次成功返回仍保留；只是新增“等待确认”状态。

## 8. 常见失败与排查

1. 现象：`/recommend/confirm` 报找不到会话。  
原因：`thread_id` 不一致或进程重启导致内存 checkpointer 丢失。  
处理：确认 `session_id` 一致；开发阶段避免服务重启；生产可换持久化 checkpointer。

2. 现象：`/recommend` 一直直接 success，没有进入确认。  
原因：没有命中 RAG 路由。  
处理：换技术类 query，确保 `routing_node` 选择 `rag`。

3. 现象：`pending_sub_questions` 为空。  
原因：上游任务拆解失败。  
处理：检查 `sub_question_generation_node` 的 LLM 输出与回退逻辑。
