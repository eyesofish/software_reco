# 工作流（当前计划）

## 1. 目标
- 保持当前 `/recommend` 行为稳定。
- 以最小风险新增流式输出能力。
- 引入 0.6B 小模型提升分流质量，同时保留规则稳定性。
- 通过 rerank 提升检索结果质量。

## 2. 已确认的设计决策

### 2.1 `@task` 使用范围
- `@task` **不是**给所有 node 函数统一加的。
- 当前是 StateGraph 结构，node 函数返回 `dict`。
- 推荐做法：把外部高耗时调用（LLM/搜索/网络/IO）抽成 `@task` 单元。
- 现有 `@task` 位置：
  - `nodes.py:596`
  - `nodes.py:741`

### 2.2 检索 rerank 教程（应该怎么做）
- 目标：在“向量检索 + Tavily 合并”之后、下游使用之前，增加二阶段 rerank。
- 步骤 1（开关控制）：新增/启用 `RETRIEVAL_ENABLE_RERANK`，默认 `false`，灰度时再打开。
- 步骤 2（实现函数）：在 `retriever.py` 新增 `rerank_documents(query, docs, top_n)`，输入合并后的 `docs`，输出重排后的 `top_n`。
- 步骤 3（接入点）：在 `retrieve()` 里完成 `merged_docs` 后调用 rerank，而不是在 node 层重复做。
- 步骤 4（最小可用打分）：先用可解释的线性分数（向量分 + 关键词重合分 + 来源权重），后续再替换 Cross-Encoder/LLM reranker。
- 步骤 5（返回约定）：返回前统一写回 `metadata.score`（rerank 后分数），并按降序排序，保证下游一致消费。
- 步骤 6（日志与观测）：记录 `query`、`before_count`、`after_count`、前 5 条 `doc_id+score`，便于对齐 `retrieval_recall`。
- 步骤 7（验收）：至少对比 `Recall@K / MRR / answer_correctness` 三项，确认开启 rerank 后无回归再默认打开。

### 2.3 分流策略升级
- 当前分流基于规则/分词词表。
- 引入 0.6B 小模型做分流，但采用**混合分流**：
  - 先走硬规则
  - 再走模型判别
  - 低置信度回退到现有规则/默认策略
- 不建议一步到位“全量替换规则”。

## 3. 推荐改动顺序

### 阶段一：先稳质量（先于流式传输）
1. 保留现有规则分流作为基线。
2. 接入 0.6B 混合分流：
   - 输出严格 JSON：`mode`、`confidence`、`reason`
   - 低于阈值回退（建议阈值 `0.7`）。
3. 在检索链路接入 rerank（合并后、下游使用前）。
4. 仅对外部高耗时调用增加/调整 `@task`。

### 阶段二：安全接入流式输出
1. 先定义流式协议（先不改业务逻辑）：
   - 事件类型：`started`、`progress`、`awaiting_human_confirmation`、`final`、`error`、`done`
   - 通用字段：`session_id`、`event`、`timestamp`、`trace_id`
2. 新增 `/recommend/stream`（SSE 或 `StreamingResponse`），保留旧 `/recommend`。
3. 将执行路径改为可发出“阶段级”流事件。
4. 前端按会话消费流（每个会话独立连接与 loading 状态）。

### 阶段三：增强项
1. 可选：接入 LLM token 级流式输出。
2. 在确认瓶颈后，扩展 `@task` 覆盖面。
3. 在流式链路稳定后，再评估是否弱化/下线旧非流式接口。

## 4. 验收标准
- 混合分流上线后，分流误判率下降，或至少不高于当前规则版。
- rerank 上线后，候选结果相关性稳定提升（有离线/在线对比指标）。
- 新增 `/recommend/stream` 不影响现有 `/recommend`。
- `awaiting_human_confirmation` 能正确通过流式事件传递并被前端消费。
- 会话切换时不出现 loading/流状态串话。

## 5. 实施备注
- 建议以开关方式渐进发布：
  - `ROUTING_USE_SMALL_MODEL`
  - `RETRIEVAL_ENABLE_RERANK`
  - `RECOMMEND_ENABLE_STREAM`
- 新链路统一使用结构化日志（分流决策、rerank 分数、stream 事件）。
